# 制谱说明

本目录放 Arivento 的谱面（`.txt`）和对应音乐（`.mp3`）。这份说明面向接手制谱的人或 AI：写出的谱面要能被 AriventoCreator 打开，也要能被 App 导入。

## 文件约定

- 谱面和音乐放在一起，同名：`曲名.txt` 配 `曲名.mp3`。一首歌有多个难度时建一个子目录，例如 `IH_Luogu/0.txt`～`4.txt` 加一份音乐。
- 文件用 UTF-8 编码，不带 BOM 也可以。整份谱面写在一行 JSON 里即可。
- 本目录会整体进入公开仓库 `zyxjeek/Arivento`，放进来的音乐也会公开。

## 格式

```text
["名称","音乐文件名",历史过屏时间,模式,BPM,每拍细分,结束时间,[音符,...]]
//tags:[["副歌",8000],["尾奏",45000.5]]
```

| 位置 | 含义 | 取值 |
| --- | --- | --- |
| 1 名称 | 显示在 App 里 | 非空字符串 |
| 2 音乐文件名 | 只作记录，玩家在手机上自己选音乐 | 字符串，通常写同名 mp3 |
| 3 历史过屏时间 | 制谱时的预览参数，App 游玩用玩家自己的设置 | 大于 0，常用 500 |
| 4 模式 | 2：Creator 把第一个音符的头时当作网格偏移；1：网格从 0 开始 | 新谱写 2 |
| 5 BPM | 网格用 | 20～400，可带小数 |
| 6 每拍细分 | 网格用 | 1～64，常用 4 |
| 7 结束时间 | 毫秒，游戏到这里结束 | 至少比最后一个头或尾晚 500 |
| 8 音符列表 | 见下文 | 1～100000 个 |

第二行 `//tags:` 可以省略。标签是 `[名称, 毫秒]`，名称非空，时间 0～7200000，最多 1000 个。App 只读第一行的 JSON，标签只给 Creator 用。

### 音符

- Tap：`[轨道, 头时]`；Hold：`[轨道, 头时, 尾时]`。
- 轨道是整数 1～4，从左到右。时间单位是毫秒，从音乐开头算起，可以带小数，保留 6 位以内。
- 头时 ≥ 0，尾时不超过 7199500。
- 整个列表按头时从小到大排列，头时相同时按轨道排列。
- Hold 的尾时必须晚于头时。
- 同一轨上，下一个音符的头时必须**晚于**上一个音符的尾部：Tap 的尾部就是头时，Hold 的尾部是尾时，相等也不行。
- 不同轨可以同时。头时完全相同的音符是多押，游戏里带金色边框。

## 算时间

网格间隔是 `60000 / BPM / 每拍细分` 毫秒。设第一拍在音乐里的时间是 `offset`（毫秒），第 k 格的时间是：

```text
t = offset + k × 60000 / BPM / 每拍细分
```

结果四舍五入到 6 位小数，和 Creator 吸附的精度一致。例如 BPM 136、细分 4、offset 1323.529412 时，间隔是 110.294118ms，第 8 格是 2205.882353。

- 模式 2 下，Creator 打开谱面时把第一个音符的头时当作 offset，所以第一个音符应该落在拍上，后面的音符才能和网格对齐。
- 需要三连音等其他节奏时，可以把细分设成 3、6、8、12，或者直接写不在网格上的时间。不在网格上的音符在 App 里照常游玩，只是在 Creator 里吸附时会移到最近的格子。
- 变速歌曲只能选一个 BPM 作网格，其余部分直接写毫秒。

## 游戏规则

写谱时要考虑这些规则：

- **判定**：按下时间和头时相差 ≤80ms 为 Perfect，≤160ms 为 Good，再晚就是 Miss。准确率 =（Perfect + Good × 0.65）/ 已结算数。
- **Hold**：按下头部时记住等级，一直按到尾时才结算并加连击；中途松手或滑出本轨就是 Miss。
- **输入**：四条轨道是四块独立的触摸区，可以多指同时按。玩家多数用两只拇指或四指平放。
- **延迟**：玩家的谱面延迟会让头和尾一起平移，制谱时不用补偿。
- **练习模式**：玩家可以只玩一段时间，只保留头时在这段里的音符。标签的位置适合作为练习的起点。

## 写谱建议

- 音符跟随音乐里清楚的声音：鼓点、主旋律、人声字头。长音用 Hold，Hold 的尾部放在音结束或下一个重拍上。
- App 开局有 3 秒倒计时，音乐从 0ms 开始播放，所以音符可以从 0ms 开始。
- 双押最常用；三押、四押留给重音或段落结尾。四押时玩家双手都被占用，前后要留空。
- 同一只手不要连续快速按同一轨。快速段落让左右手交替（1、2 轨和 3、4 轨）。
- Hold 按住期间，另一只手可以继续点别的轨，但不要在 Hold 所在的手那一侧安排密集音符。
- 密度从前往后逐渐变化，副歌最密。下面的数据可以参考。

## 检查

写完用下面的脚本检查。它按本说明的全部格式要求检查，比 Creator 和 App 导入时都严：Creator 会自动补足结束时间、合并同轨同时的重复 Tap，脚本把这两种情况都当作错误。没有输出就说明格式正确：

```python
import json, sys

def check(path):
    raw = open(path, encoding='utf-8-sig').read().strip()
    body, _, tags = raw.partition('\n//tags:')
    a = json.loads(body)
    num = lambda x: isinstance(x, (int, float)) and not isinstance(x, bool)
    assert isinstance(a, list) and len(a) == 8, '必须是八项列表'
    name, music, approach, mode, bpm, div, end, notes = a
    assert isinstance(name, str) and name.strip() and isinstance(music, str), '名称或音乐名不对'
    assert num(approach) and approach > 0 and mode in (1, 2), '过屏时间或模式不对'
    assert num(bpm) and 20 <= bpm <= 400 and num(div) and 1 <= div <= 64, 'BPM 或细分超出范围'
    assert isinstance(notes, list) and 0 < len(notes) <= 100000, '音符数量不对'
    tail, prev = {}, -1
    for i, n in enumerate(notes, 1):
        assert isinstance(n, list) and len(n) in (2, 3), f'第 {i} 个音符不是二项或三项'
        lane, head, last = n[0], n[1], n[-1]
        assert lane in (1, 2, 3, 4) and num(head) and num(last) and head >= 0 and last <= 7199500, f'第 {i} 个音符轨道或时间超出范围'
        assert head >= prev, f'第 {i} 个音符没有按头时排序'
        assert len(n) == 2 or last > head, f'第 {i} 个音符 Hold 尾时不晚于头时'
        assert head > tail.get(lane, -1), f'第 {i} 个音符和同轨上一个音符重叠'
        tail[lane], prev = last, head
    assert num(end) and end >= max(tail.values()) + 500 and end <= 7200000, '结束时间要比最后一个头或尾晚至少 500ms'
    if tags:
        t = json.loads(tags)
        assert isinstance(t, list) and len(t) <= 1000 and all(
            isinstance(x, list) and len(x) == 2 and isinstance(x[0], str) and x[0].strip()
            and num(x[1]) and 0 <= x[1] <= 7200000 for x in t), '标签格式不对'

for p in sys.argv[1:]:
    try: check(p)
    except Exception as e: print(p, e)
```

保存为脚本后运行 `python check_chart.py 谱面.txt`。最后可以用 Creator 打开谱面，试听一遍。
